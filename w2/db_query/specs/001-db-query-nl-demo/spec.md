# Feature Specification: 数据库连接与自然语言查询（db-query-nl-demo）

**Feature Branch**: `001-db-query-nl-demo`  
**Created**: 2026-04-28  
**Status**: Draft  
**Input**: 数据库查询工具：用户添加数据库连接；系统拉取并展示表/视图元数据；支持手写只读 SQL 与自然语言生成 SQL；将连接信息与元数据持久化到本地存储，并可复用由目录信息整理而来的结构化描述；自然语言路径需配置语言模型访问方式（含凭证），支持保存以便下次使用；执行前仅允许单条只读查询、默认行数上限、注入防护；结果以结构化形式交付以便表格呈现。（来源：`instructions.md`「基本想法」第 12–21 行）

**相关分析**：同目录 `analysis.md`

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 添加连接并浏览表与视图（Priority: P1）

作为使用者，我希望输入数据库连接信息并让系统连上我的库，在同一会话内看到可用的表与视图清单，以便确认连接正确并了解可查询对象。

**Why this priority**：后续查询与自然语言生成都依赖正确的连接与模式可见性；没有浏览能力则工具不可用。

**Independent Test**：在隔离环境中配置一条有效连接，断言界面或等价接口返回非空的表/视图列表（或空库时返回明确空状态）。

**Acceptance Scenarios**:

1. **Given** 用户提交了有效的连接配置，**When** 系统完成连通性与元数据拉取，**Then** 用户看到表与视图列表（或「无表」的可读说明）。
2. **Given** 连接无效或目标不可达，**When** 用户尝试连接，**Then** 系统给出可行动的错误说明且不声称已成功加载模式。

---

### User Story 2 - 只读 SQL 查询并查看表格化结果（Priority: P2）

作为使用者，我希望手写一条只读查询并看到列与行结果（表格形式），以便直接探查数据。

**Why this priority**：手写 SQL 是除自然语言外的基础路径，也是验收与排错的重要手段。

**Independent Test**：对已知 seed 或测试库执行一条合法单条 `SELECT`，断言返回列元数据与行数据与预期一致；对非法输入断言拒绝且不执行数据访问。

**Acceptance Scenarios**:

1. **Given** 已建立有效连接，**When** 用户提交通过校验的单条只读查询，**Then** 用户在同一界面看到表格化（或等价的行列）结果。
2. **Given** 用户输入非只读、多语句或语法错误，**When** 提交执行请求，**Then** 系统在访问数据前拒绝并提示原因。
3. **Given** 查询未指定行数上限，**When** 执行成功，**Then** 返回行数不超过约定上限（见 FR），且用户能察觉结果被限制（例如提示或摘要）。

---

### User Story 3 - 自然语言生成查询并复用语义模型配置（Priority: P3）

作为使用者，我希望用自然语言描述意图并得到可执行的只读查询；系统应结合当前库的表/视图上下文生成 SQL；我需要选择或录入语言模型服务及凭证并能在下次复用，以便减少重复配置。

**Why this priority**：体现差异化能力；依赖 P1/P2 已提供的连接与校验机制。

**Independent Test**：在固定 schema 与固定提示词策略下，用若干黄金问句验证生成的 SQL 通过静态校验且在同一数据库上执行结果符合约定；凭证不落库的验收走宪章与环境变量约定。

**Acceptance Scenarios**:

1. **Given** 已连接且元数据可用，**When** 用户输入自然语言请求并触发生成，**Then** 系统结合当前模式上下文产出一候选 SQL，并在执行前经过与用户手写 SQL 相同的只读与安全校验。
2. **Given** 用户首次配置语言模型端点与密钥，**When** 保存设置，**Then** 后续会话可加载该配置而无需重新录入（密钥处理须符合组织密钥策略与宪章）。
3. **Given** 语言模型不可用或返回不可执行语句，**When** 用户尝试生成，**Then** 系统给出可读失败原因且不执行未通过校验的 SQL。

---

### Edge Cases

- 连接串正确但权限不足，无法读取目录视图时，应说明权限/对象可见性问题。
- 大型库（极多表/列）时，列表或上下文摘要应仍可加载或在合理时间内降级提示。
- 自然语言歧义或超出 schema 时，应提示无法生成或需澄清，而非执行高风险猜测。
- 结果为空集与错误状态应区分展示。
- 重复添加同名或等价连接时的合并/覆盖策略由实现定义，但用户须能辨识当前生效连接。
- 用户尚未保存任何语言模型配置时，自然语言生成路径 MUST 引导用户完成端点与凭证录入后才能继续（或明确降级为仅手写 SQL）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：系统 MUST 允许用户注册至少一条数据库连接（例如连接地址与凭据），并 MUST 在成功后持久化连接配置供后续使用（不含将密钥写入公开版本库；遵循宪章与密钥实践）。
- **FR-002**：系统 MUST 从已连接的数据库拉取表与视图级元数据，并在界面中展示；并 MUST 将拉取到的结构化元数据缓存在本地应用存储中以便复用与离线展示（在连接可用性允许范围内）。
- **FR-003**：系统 MUST 允许用户手写提交查询；在执行前 MUST 使用解析/结构化校验，仅允许**单条**只读 `SELECT`；语法或策略不满足时 MUST 拒绝执行并给出提示。
- **FR-004**：当用户查询未包含行数限制约定时，系统 MUST 自动施加默认最大行数（**1000 行**），并 MUST 让用户能理解结果被截断或受限。
- **FR-005**：系统 MUST 通过参数化或等价结构性检查（例如 AST 策略）阻止 SQL 注入与越权构造；禁止执行未通过检查的语句。
- **FR-006**：系统 MUST 支持自然语言生成查询：生成时 MUST 使用当前已缓存或 freshly 拉取的表/视图信息作为上下文输入给语言模型流程。
- **FR-007**：系统 MUST 允许用户选择或录入语言模型服务端点及凭证，并 MUST 持久化非密钥或可接受形式的配置以便下次选择；密钥 MUST 符合最小暴露原则（环境变量或安全存储，不在规格中规定具体产品）。
- **FR-008**：查询执行结果 MUST 以结构化载荷形式返回（列与行），以便前端以表格呈现；错误与空结果 MUST 可区分。
- **FR-009**：系统 MUST 在无登录前提下可用（与项目宪章一致）：不对访问做身份鉴别；部署侧仍须自行限制网络暴露。

### Key Entities *(include if feature involves data)*

- **数据库连接**：用户定义的逻辑连接（标识、连接参数引用、最近连通状态）；不包含明文秘密在规格层定义。
- **模式元数据**：表、视图及列等描述信息，用于展示与自然语言上下文。
- **语言模型配置**：提供商标识、端点、密钥引用方式、选用状态。
- **查询请求**：手写 SQL 文本或自然语言文本及关联的连接上下文。
- **查询结果**：列定义、行数据、截断/限制标记、错误信息（若有）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：在测试环境中，使用有效连接配置的用户可在**一次会话内**完成「添加连接 → 看到表/视图列表」且无误导性成功提示。
- **SC-002**：对一组代表性注入与滥用样例（多语句、非只读意图、明显注入负载），系统在访问目标数据库数据前的拦截率为 **100%**，并返回可读原因。
- **SC-003**：对未带行数限制的合法只读查询，任何成功执行的响应所含数据行数**不超过 1000**，且用户可获知存在上限或截断。
- **SC-004**：在已配置语言模型且元数据可用的条件下，黄金自然语言问句集合（规格阶段不少于 **5** 条，在计划中固化）中至少 **80%** 能在首轮生成通过校验的 SQL 并在测试库上执行成功；其余 MUST 失败明了而非静默错误结果。

## Assumptions

- 首个版本以外部 **PostgreSQL** 兼容库为主要连通与目录信息来源（与产品说明一致）；其他数据库引擎可作为后续扩展，不阻塞本规格验收路径。
- **本地持久化**：连接串、缓存的模式元数据、以及语言模型端点与凭证的可复用配置（凭证按安全策略存放，不进入版本库）保存在产品侧的本地嵌入式存储中，以便跨会话复用；不要求多端实时同步。
- 表/视图目录信息经整理后形成可复用的结构化描述并写入上述本地存储，供列表展示与自然语言上下文加载；完整刷新策略（何时重新拉取目录）由计划在非功能需求中细化。
- 自然语言生成路径需用户选择或录入语言模型服务；若无已保存选项，用户仍可手动输入并完成保存以便后续选用。
- 语言模型调用失败或不可用时，用户仍可仅使用手写 SQL 路径；US3 验收是否在计划中强制启用 LLM 由计划阶段约定。
- 表格呈现为展示层职责；本规格仅要求返回结构化行列数据足以驱动表格，且错误与空结果可区分。
